# KaiBoard 安全说明（Security）

> **English.** KaiBoard has no server and no account — your board data is never uploaded. The real risks are not on the network; they are (1) cloud-drive sync overwriting files, (2) the fragility of browser local storage, and (3) who can reach the optional Agent co-draw relay on your machine. This document states plainly what is protected and what is **not**.

结论先行：**KaiBoard 没有服务器、没有账号、不上传任何数据**。主要风险不在网络，而在
①云盘同步的覆盖 / 冲突，②浏览器本地存储的脆弱性，③Agent 共绘的"最后一公里"注入方。
本文如实列出已做的与**尚未做的**（§6 已知限制）。

---

## 1. 数据在哪里 —— 三种存放位置

| 存放位置 | 何时使用 | 谁能读到 | 风险点 |
|---|---|---|---|
| **浏览器 IndexedDB**（默认） | 不设置文件夹时 | 只有同一浏览器、同一 origin 的页面 | 清理浏览器数据 / 换浏览器 / 无痕模式 → **数据全没** |
| **本地文件夹**（File System Access） | 设置里选了文件夹 | 该电脑上任何能读这个目录的程序 | 明文 JSON，无加密 |
| **云盘同步目录**（本地文件夹的一种） | 文件夹选在 OneDrive / 坚果云 等 | 你的云盘账号 + 云厂商 | 明文上云；多机覆盖（见 §2） |

- 文件结构：`<所选文件夹>/kaiboard-data/tree.json` + `boards/<id>.json`。
- **没有后端**：KaiBoard 是纯静态站点，不存在"上传到 KaiBoard 服务器"这回事。托管方只发给你 HTML/JS，看不到你的画板。
- 偏好项（语言 / 主题 / 文件夹句柄 / Agent 令牌）**永远存 IndexedDB**，不进文件夹 —— 因为文件夹句柄本身就记在这里。

## 2. 云盘多机同步：覆盖逻辑

### 2.1 曾经的隐患

早期版本「选择文件夹」是**无条件把本机数据整体写进去**，从不先读文件夹里已有什么。于是：A 电脑攒了 30 个画板同步到云盘 → B 电脑第一次用（本地只有 1 个新建画板）→ B 把设置指向同一个云盘目录 → B 的目录树只有 1 个节点，**整体盖掉** A 的 30 节点目录 → 云盘把它同步回 A → **A 看到自己只剩 1 个画板**。
（A 的 30 个 `boards/<id>.json` 其实还在磁盘上没被删，但目录树里没有它们了，KaiBoard 不再显示 = 事实上的数据丢失。）

### 2.2 现在的行为

选择文件夹时先**只读探测**（不创建目录、不写任何字节）。若文件夹里已有 KaiBoard 数据，弹窗让你**显式三选一**，绝不静默决定：

| 选项 | 行为 | 何时用 |
|---|---|---|
| **合并（推荐）** | 两边按 id 求并集：文件夹独有的照单收下，本机独有的写进去；同 id 两边都有 → `updatedAt` 新的胜出 | 默认。多机来回用就选它 |
| **以文件夹为准** | 本次**一个字节都不写**，直接采用文件夹现有数据。本机浏览器里的旧数据留在原处不删 | 新电脑接入既有云盘目录 |
| **以本机为准（覆盖）** | 用本机数据改写目录树（红色危险按钮 + 明示后果） | 确认文件夹里是过期数据 |

id 是 UUID，跨机不会误撞；同 id 必然是同一个逻辑节点经云盘同步而来，所以"按 id 合并"语义正确。

### 2.3 仍然存在的固有限制（这是云盘的性质，不是 bug）

- **同一时刻两台电脑都在改** → 云盘按文件级"最后写入胜出"，晚保存的那台会盖掉先保存的。KaiBoard 不做 CRDT/OT —— 定位是**个人多机先后使用**，不是多人实时协同。
- **正确用法**：一台用完等云盘同步完成，再开另一台。
- 云盘自身一般有历史版本，误覆盖可从云盘回收站 / 版本历史找回 —— 这是当前唯一的"后悔药"，建议开启。

## 3. Agent 共绘的安全模型

Agent 共绘是一个**可选**能力：让 AI Agent 在你的画布上实时增删元素。它默认关闭，开启后也只在本机回环地址上通信。完整说明见 [`docs/AGENT.md`](./AGENT.md)。

### 3.1 已经做到的

1. **默认关闭（Opt-in）**：AI 面板里不开启「Agent 共绘」，页面**不会轮询**任何本地端口，外部完全驱动不了。关闭 = 断开。
2. **页面自带轮询客户端**：KaiBoard 页面自己长轮询 `127.0.0.1:8787`，收到指令后走同源校验。普通用户不需要装脚本或粘贴代码。
3. **令牌校验 + 同源校验**：
   - **中继令牌**：外部进程要连 `127.0.0.1:8787` 必须带对令牌，否则 403。中继随机生成并持久化（跨重启稳定）。
   - **显式授权**：MCP 侧只读环境变量 `KAIBOARD_TOKEN` —— 由**你**从 **✨ AI → AI 面板** 复制粘贴，不自动抓取。**没有你的显式授权，任何 Agent 都连不上你的画布。**
   - **同源强制**：页面侧强制 `origin === window.location.origin`，跨域页面发的消息直接拒绝。
4. **中继只绑 `127.0.0.1`**：不监听 `0.0.0.0`，同一 Wi-Fi 下的别人扫不到、连不上。
5. **不出网**：中继与页内片段只跟本机回环地址通信，不向任何外部服务器发送画板内容。
6. **本体保持纯静态**：KaiBoard 自己不开任何监听端口；端口这件事由那个可选的外部组件承担。
7. **整板替换自动快照**：整板替换执行前会把当前画板元素保留到本地快照队列（最多 20 份），误覆盖后可从「AI 面板 → 快照还原」还原。
8. **可审计**：中继与页内客户端都是明文源码，可以逐行读。

### 3.2 当前的薄弱环节

- **同机其他进程**：中继开着时，本机上任何知道令牌的程序都能发指令。缓解手段是"令牌 + 仅在开启时监听"，不是绝对隔离。
- **令牌的自动发现**：页面侧经只读端点 `GET /info`（仅 `127.0.0.1` 可达）读取令牌以做到"零手动填写"。这意味着**本机上任何进程**都能读到该口令 —— 但中继本就只绑回环地址，能读它的程序通常也已经能读你的浏览器存储。因此这是**可接受的本机取舍**。若你要更严的隔离，可改用自行设定固定令牌的方式。

## 4. 威胁模型速查：谁能看到什么

| 角色 | 能看到你的画板吗 | 说明 |
|---|---|---|
| 静态站点托管方 | ❌ | 只发前端代码，数据从不上行 |
| 同一 Wi-Fi 的陌生人 | ❌ | 中继绑 `127.0.0.1`，不对外 |
| 云盘服务商 | ✅（若用云盘目录） | 明文 JSON，等同于把文件放网盘 |
| 同一台电脑的其他用户 / 程序 | ✅（若用本地文件夹） | 就是普通文件，受操作系统权限保护 |
| 你安装的浏览器扩展 | ✅ | 扩展本就有整页权限（与是否开共绘无关） |
| 外部 AI Agent | 仅在你**开启共绘且给了令牌**时 | 关闭即断 |

## 6. 已知限制（诚实列出）

| # | 限制 | 影响 | 现状 |
|---|---|---|---|
| 1 | 文件夹里的数据**明文未加密** | 拿到文件即可读 | 定位是个人白板，暂不加密；敏感内容建议别放云盘目录 |
| 2 | Agent 令牌明文存 IndexedDB | 同机程序理论可读 | 低危（同机本就可读文件）；后续评估更严的存取方式 |
| 3 | **敏感动作目前只提示、需自查快照**：整板替换会弹提示并自动留快照，但**没有二次确认弹窗** | Agent 误操作可能整板覆盖 | 已内置自动快照（最多 20 份）+ 可还原；二次确认 UI 待评估 |
| 4 | 无操作审计日志 | 事后查不到"谁改了什么" | 待办 |
| 5 | 无内置版本历史 / 快照 | 误删误覆盖只能靠云盘版本 | 待办 |
| 6 | 浏览器清数据 = IndexedDB 全丢 | 默认存储下的最大丢数据风险 | 已在设置里提示；建议切文件夹存储 + 定期「导出全部」 |

---

## 7. 给用户的四条实用建议

1. **重要内容切到文件夹存储**，别只躺在浏览器 IndexedDB 里（清缓存就没了）。
2. **文件夹选在带版本历史的云盘目录**，等于白送一份"后悔药"。
3. **多机不要同时开**，一台用完等同步转完再开另一台。
4. **不用 Agent 共绘时，保持开关关闭** —— 关闭即断开，最小化暴露面。
